# Tuvis World｜一致性、素材指代与路径复核

日期：2026-10-19（Asia/Shanghai）

范围：当前需求说明书、执行计划、交接说明及 tuvis-world/05_handoff/v1/；不包含已停用的探索稿作为执行依据。

## 1. 本轮发现并修正

| 项目 | 修正结果 |
|---|---|
| 首页入口文案不一致 | 首屏和工坊分区统一为“进入兔维斯工坊” |
| 内容数据来源与面板目录不一致 | 文案源为资源包content JSON；发布到public/world/v1；内容面板统一在src/world/content |
| 首页加载连带要求工坊数据 | WorldContentBundle/loadWorldContent与WorldBundle/loadWorldData分离，首页不请求scene JSON或工坊核心图片 |
| 内容面板与工坊面板类型耦合 | ContentOverlay只处理图文；维修与组装由工坊侧分派，首页无需场景数据或工坊代码 |
| 安装完成与陈列事件归属不清 | 组装面板只安装；到达装备架的物件处理器才发PLACE_ON_RACK |
| 日常动作位置和坐姿深度不充分 | 站姿动作沿用物件靠近点；坐姿给定椅座、归一化公式和depth626；保留导航脚底 |
| 计划中多处裸文件名 | 每个Files清单补成完整项目相对路径；.nvmrc明确为新建 |
| 素材总览使用简写/通配符 | 17张图片逐项给出资源ID、项目路径、使用位置与负责任务，需求书和计划使用相同映射 |
| README局部路径和机器路径记录 | 补全项目路径，区分项目路径/包内路径/URL；归档记录移除本机绝对路径 |
| 资源引用校验范围不足 | 增加核心图片、内容主图、组装/陈列帧、模块、世界/门内容及坐姿深度校验 |

## 3. 路径约定

执行命令和文档中的文件路径相对项目根目录。未来要创建的源码文件可以不存在，但必须给出完整相对路径。
JSON内部路径相对资源包根目录，按manifest映射为项目路径和发布URL；HTML和Markdown链接相对所在文件，保持文件移动后的可点击性。网页/zh/world等是URL路由，不是本机文件路径。
原图出处仅用于来源记录，不构成运行时依赖；云端运行资源以manifest中的交付副本为准。

## 4. 可重复的复验

~~~bash
node tuvis-world/05_handoff/v1/tools/verify-pack.mjs
node tuvis-world/05_handoff/v1/tools/audit-handoff.mjs
~~~

两项检查预期均输出PASS。第一项验证图片/裁切/数据/哈希和导航，第二项验证17/17素材映射、9任务文件路径、关键跨文档约定、相对链接及当前交接包机器路径。
交接ZIP还应在临时目录解压后重复执行，检查文档和资源引用是否仍成立。

本轮核对不等于产品代码、实际碰撞运行或双系统验收已完成；这些由计划中的测试和验收任务验证。
