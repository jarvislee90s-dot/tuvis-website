- 版本：v2.1
- 日期：2026-10-19（Asia/Shanghai）
- 状态：已批准；已纳入用户补充的住宅场景与扩展门要求
- 项目目录：tuvis-website
- 交付对象：电脑浏览器用户；在云端沙箱执行实现任务的 Agent。

## 路径约定

所有执行命令均在项目根目录 tuvis-website 下运行；正文中的文件路径均以项目根目录为基准。Markdown 跳转链接使用相对所在文档的链接，保持复制项目后可点击。/zh/world 等是网页路由，不是文件系统绝对路径。manifest 内部资源路径相对资源包根目录，按第7节映射为项目路径和发布 URL。

## 1. 产品目标与交付结构

在现有兔维斯产品官网中增加“兔维斯世界”导航，建立原创角色 IP 的专题官网。访客先进入以图片、文字和内容卡片为主的展示页，再从其中的工坊分区进入可操作的房间体验。

交付包含两个连续部分，使用同一套导航、内容和素材：
1. 专题展示页：建立角色、装备、世界、故事的初始展示，以及工坊体验入口。
2. 工坊互动页：完成一个固定斜俯视房间内的探索与 Bug Buster 组装体验。

建设顺序为“专题展示页 → 工坊互动页 → 两页集成与部署验收”。本说明书同时规定两部分需求。

## 3. 专题首页展示需求

### 3.1 版式与视觉基准

参考[未来世界概念设定板](../../../tuvis-world/兔维斯未来世界概念设定板.png)右下角“官网角色专区概念”的主视觉与卡片层级，按本节规定的栏目组织页面。

画面采用明亮、色彩鲜明的科技动画风。现有角色图、工坊图、回路城图作为主要视觉，正文采用正常网页排版。中文文字由网页呈现，保证清晰可读、可选择和可维护。

桌面页面采用居中内容区；首屏使用大幅主视觉，后续采用留白清楚的图文区块与卡片网格。图区与正文保持合理对比，模块内的操作按钮和状态样式统一。

### 3.2 内容模块

| W-02 | 认识兔维斯 | 人物简介、三个性格标签、HUD 护目镜与胡萝卜核心等特征 | 查看角色图和简洁说明 |
| W-03 | 装备图鉴 | 四件装备的图片、名称、身份色、功能及代码编辑类比 | 选中卡片，在统一详情区展开说明 |

每个已显示的卡片与按钮均有实际内容或有效目标。故事卡片的操作文案为“查看简介”，其内容状态与已提供正文保持一致。所有信息区在工坊运行素材尚未加载时仍可正常阅读。

兔维斯是年轻发明家和问题解决者，性格聪明、机灵、可靠、略带俏皮；世界基调为科技轻喜剧。回路城是多种智慧生命共同生活的未来城市。

故事卡片为《完美的一天，差一点》《谁动了我的零件？》《最厉害的武器》，简介依据现有中文文案。居民图文使用已确认的类别与世界基调，具体固定配角须有正式设定依据。

## 4. 工坊互动需求

### 4.1 场景与外围

视觉基准为[斜俯视工坊方向图](../../../tuvis-world/03_exploration/workshop-isometric-direction-v1.png)的镜头、画风与空间气质。运行素材由干净背景、独立角色、物件与前景遮挡层组成。

房间采用固定斜俯视镜头；家具顶面、地面前后关系、角色脚底与投影保持同一透视。外围采用住宅剖面与地面环境延伸：可见庭院步道、相邻住宅、管线、植被与远景。

工坊是兔维斯家中的一个房间，建筑与周围地面、庭院和住宅结构相连。场景保留两处门/门洞，表现家中其他空间的存在，并作为后续场景扩展位置。本期点击门时展示去向说明，活动范围保持在工坊内。

可见范围、可走范围、可交互范围分别定义。房间内的通行边界由墙体、栏杆、花槽、设备和地面结构表现，并与实际碰撞边界对齐。外围环境提供世界延伸感，角色沿房间内的合法通道活动。

### 4.2 操作与导航

| 编号 | 需求 |
|---|---|
| I-01 | 界面显示“点击地面移动”“点击物件，兔维斯会走近并互动”，并提供“操作说明”按钮 |
| I-02 | 点击有效地面后，角色沿可达路线移动到目的地 |
| I-03 | 点击物件后，角色走到该物件的靠近点，到达后触发内容或动作 |
| I-04 | 新的目的地替换先前目标，并取消先前尚未触发的到达事件 |
| I-05 | 路线绕开墙与家具；不可达目标保持原位并给简短反馈 |
| I-06 | 阅读、图鉴、维修和组装面板打开时暂停场景移动；关闭后回到原位置 |
| I-07 | 切换窗口或标签时停止移动与拖拽；恢复时保持有效状态 |
| I-08 | 场景按桌面窗口等比缩放，点击位置按实际显示区域换算 |

角色以脚底为定位锚点。导航数据包括可走多边形、障碍多边形、角色足迹、路径节点、连通边、出生点、物件靠近点和动作停靠点。

采用人工标注的通道图与最短路径计算。路径边及移动过程均检查可通行性，防止角色穿墙、穿家具、越过外沿或在大帧间隔下跨越障碍。实际坐标基于最终场景素材标注。

### 4.3 物件互动

| 位置 | 互动内容 |
|---|---|
| 窗户 | 查看回路城与窗外景物介绍 |
| 居民海报 | 查看居民类别和简短世界观说明 |
| 工具箱 | 浏览四装备图鉴，领取主线模块 |
| 工作台 | 查看任务、维修能源匣、进入组装特写 |
| 桌椅/休息处 | 坐下与起身 |
| 咖啡机 | 持杯/喝咖啡的日常动作 |
| 装备架 | 陈列成品、再次查看和展示 Bug Buster |
| 书架/阅读角 | 打开与专题首页一致的故事简介 |
| 通往家中其他区域的门 | 展示去向说明，保留后续场景连接数据 |

世界观介绍可继续展开阅读；领取任务物件和日常探索保持顺畅。所有物件均有可到达的靠近点，热点名称在悬停或选中时可见。

### 4.4 Bug Buster 主线

任务名称：“让 Bug Buster 重新上线”。目标体验时长约 3–5 分钟。任务由寻找、维修、组装与陈列构成同一条完整体验。

| 步骤 | 角色行为 | 反馈 |
|---|---|---|
| 1 | 到工作台查看待组装的 Bug Buster 主体 | 展示三个模块轮廓和简短任务提示 |
| 2 | 在工具箱领取瞄准模块 | 更新任务槽，并可查看装备图鉴 |
| 3 | 在居民海报附近收纳盒取得能源匣 | 更新任务槽，并可查看居民介绍 |
| 4 | 在窗边储物位置取得脉冲发射头 | 更新任务槽，并可查看回路城 |
| 5 | 回工作台检查能源匣，选择松动接口并执行检查 | 接口恢复、供能检查通过 |
| 6 | 在特写界面把三个模块装入对应位置 | 卡入反馈、能源环亮起、显示完整成品 |
| 7 | 展示成品并放到装备架 | 装备架出现 Bug Buster，任务完成 |

三个模块可任意顺序领取，任务栏显示三个模块槽。集齐三件并修好能源匣后进入组装；提示明确指出当前所需动作。误操作不丢失模块，已领取或安装的模块不会被重复消耗。组装完成后返回房间，走近装备架完成陈列；组装面板只完成安装，陈列完成事件由到达装备架触发。

特写采用固定三分之四角度，提供整体放大。支持拖拽吸附，也支持“点击零件 → 点击插槽”。归位过程使用平面位移、轻微转角和卡入闪光；结束时过渡到完整成品图。

维修界面采用网页绘制的接口示意。任务状态以已领取模块、能源匣维修标志、已安装模块和完成标志统一计算。

### 4.5 角色、遮挡与日常表现

准备四个匹配斜俯视镜头的角色朝向图，移动时切换朝向并配合轻微起伏及脚下投影。坐下、持杯、持装备展示使用对应镜头的独立姿态和短过渡。

点击新目的地可结束日常动作并恢复站姿。日常动作不改变主线进度。

底图包含地面、墙与固定背景物件。角色可能从前后经过的家具采用透明独立层，按脚底与物件地面锚点进行深度排序；跨越多个深度的物件拆成前后层。碰撞决定通行，图层决定遮挡，两者分别验证。

### 4.6 进度与恢复

使用带版本号的本地存档保存主线进度和操作提示状态。刷新后恢复有效进度；损坏或不兼容存档安全重置。存储不可用时保持当前会话可完成体验。

提供“重玩主线”，执行前说明将清除本地主线进度。阅读面板和组装按钮可通过 Tab 访问，Esc 关闭当前面板。

## 5. 技术栈与代码范围

沿用现站技术，不通过新增应用或原生运行环境承载体验。

| 层次 | 规定技术 | 用途 |
|---|---|---|
| 页面与语言路由 | React 19、React Router 7 | 专题首页、工坊页、导航与语言入口 |
| 类型与构建 | TypeScript 5.7、Vite 6 | 类型约束、资源打包与静态构建 |
| 样式 | Tailwind CSS 4、普通 CSS | 图文排版、桌面布局、面板、提示与卡片 |
| 场景显示 | HTML 图层、透明 PNG/WebP、SVG | 背景、角色、深度遮挡、热点与维修示意 |
| 动效 | Framer Motion 12、requestAnimationFrame | 面板过渡、位置更新与轻量角色动作 |
| 互动状态 | Zustand 5 | 移动目标、当前面板、日常动作与任务状态 |
| 语言资源 | i18next 24、react-i18next | 导航与界面中英键对齐 |
| 进度存储 | 浏览器 localStorage | 本地主线进度与提示状态 |
| 开发/构建环境 | Node.js 22、pnpm 10.20.0、仓库锁文件 | 与现站 CI 一致的依赖安装和构建 |
| 发布 | 现有 GitHub Actions、GitHub Pages | 发布静态 dist 资源 |

产品运行只加载部署站点提供的代码、图片和内容。新增专区的内容与任务在浏览器本地运行，访客使用普通电脑浏览器即可完成体验。

工程按页面、展示内容、场景数据、导航、场景显示、互动控制和任务状态拆分。职责分布：

~~~text
src/pages/WorldPage.tsx
src/pages/WorkshopPage.tsx
src/world/
  types.ts        数据与接口类型
  content/        图鉴、世界、故事、门与说明面板
  landing/        专题首页图文区块
  scene/          场景显示、导航、物件互动
  quest/          模块领取、维修、组装与存档
  assets/         manifest、内容JSON、场景数据与图片加载入口
public/world/     实际发布的图片与静态数据
~~~

内容源文件统一为 tuvis-world/05_handoff/v1/content/world.zh.json，导入后发布到 public/world/v1/content/world.zh.json；src/world/ 保存读取、类型与界面代码。首页只加载 manifest 与内容 JSON，进入工坊后再读取 scene.json 和工坊核心图片。站点资源路径通过 import.meta.env.BASE_URL 或 Vite 导入机制生成。素材 manifest 使用相对路径，并包含图片尺寸、裁切、脚底锚点、物件地面锚点、热点、停靠点、碰撞与导航数据。

页面结构复用现有 LangLayout、TopBar 与 Footer。工坊代码在进入工坊页时加载，专题首页可以独立浏览。

## 6. 实现路径

### A. 先完成专题展示页
1. 接入 /:lang/world 和官网“兔维斯世界”导航。
2. 使用现有角色、装备、城市、工坊与故事封面完成 W-01～W-06。
3. 完成图鉴详情、故事简介、锚点导航、图片说明和内容状态。
4. 静态部分完成桌面显示、语言键、资源路径与直接刷新验证。

### B. 再完成工坊互动
1. 准备干净斜俯视背景、外围延伸、角色方向/动作与遮挡层。
2. 根据最终图片标注场景、碰撞、导航和靠近点，验证移动与遮挡。
3. 接入物件内容、主线模块、维修与组装面板、日常动作和进度恢复。
4. 从 W-06 进入工坊，从工坊返回专题首页，完成整个访问流程。

### C. 集成发布
将文案、实际使用素材、manifest 与页面代码一并构建为静态站点。完成现站测试、类型检查、子路径访问、资源失败恢复和桌面浏览器验收后发布。

详细任务拆分、实施顺序与检查命令由配套 implementation plan 承接本说明书。

## 9. 验收标准

### 9.1 专题首页
- 官网导航可以进入兔维斯世界，页面拥有独立标题、主视觉和内容层级。
- 角色、四装备、世界设定、三故事卡片、工坊体验六模块均有真实图文。
- 图鉴和简介可以展开阅读；每个显示的操作均有内容或有效目标。
- 首屏与工坊分区均可进入同一工坊页。
- 中英文界面路径可访问，内容语言说明准确；世界正文按中文内容交付。

### 9.2 工坊
- 镜头与认可的斜俯视画风一致，外围存在合理环境延伸与通行边界。
- 点击地面移动；点击物件先走近再互动；切换目标时仅当前目标触发。
- 家具与墙体被正确绕开，角色不能越过碰撞边界；前景遮挡、脚底和投影对齐。
- 可查看窗景、居民和装备；坐下、持杯、装备展示均有可见反馈。
- 任意顺序收集三模块后，可完成能源匣维修、组装、陈列和主线重玩。
- 拖拽与点击两种组装方式均可完成流程；误操作不丢失模块。
- 刷新、存储不可用、窗口失焦、资源失败与调整窗口均有可恢复行为。

### 9.3 工程与发布
- 既有测试与类型检查通过，新增导航边界和任务状态的必要验证通过。
- 部署 base、两页深链接刷新、语言导航与图片路径验证通过。
- 验收记录区分实际系统测试与浏览器引擎模拟，注明测试覆盖范围。
- 云端实现环境可实际读到所需素材和数据；发布后的访客仅使用网页即可体验。
