## 2. 需要在无生图云端交接前准备
| 缺口 | 为什么需要 | 完成证据 | 阻塞范围 |
|---|---|---|---|
| 干净斜俯视底图＋外围世界 | 当前概念图有内嵌角色与深色外围 | 无主角底图，视角不变，外围有环境延伸；用户审阅 | 正式场景 |
| 匹配镜头的四向角色 | 正面图不能直接放进新场景 | 四向透明图，造型一致、脚底锚点明确 | 走动表现 |
| 坐姿/持杯/持装备图 | 当前姿态是正面视角 | 与家具镜头匹配的姿态及停靠预览 | 日常互动 |
| 可遮挡前景透明层 | 角色需要经过家具前后 | 不重复烘焙的物件层、地面锚点与遮挡预览 | 正确遮挡 |
| 新导航与碰撞数据 | 旧数据属于正面方案 | 连通地面、障碍、足迹余量、导航节点/边、靠近点均标注并验证 | 防穿模与物件可达 |
| 新版素材 manifest | 云端不能靠本机路径或猜摆放 | 全部路径相对、尺寸/裁切/锚点/状态齐全，无悬空引用 | 云端接入 |
| 组装特写最终布局 | 独立零件接缝不保证一致 | 归位布局与成品过渡预览；模块辨识清楚 | 组装面板 |
| 所需图鉴/海报局部 | 背景图案未必适合放大阅读 | 可读面板图或明确使用既有参考的展示范围；不要求云端补画 | 内容面板 |
| ZIP 或仓库素材交付 | 本机文件不会自动出现在云端 | 解包检查、文件清单与校验，无绝对路径依赖 | 云端取得资源 |

素材生产者为当前具备生图能力的本地阶段；云端 Agent 消费图片、文本和 manifest，不承担补生图或建模。
所有必要图片保持确定的文件名、透明通道、大小写与路径；附完整提示词与素材来源。UI 提示、轮廓高亮、维修示意等可由代码绘制，不属于缺失生图能力。
旧 04_web_assets/asset-manifest.json 为 RETIRED_VIEWPOINT_REFERENCE_ONLY，旧 scene 坐标不可复用。后续应新建斜俯视 manifest，并给被替代素材明确状态。

已核实仓库有 pnpm-lock.yaml；React / Framer Motion / Zustand 等既有依赖可支持本稿方案。
2026-10-19 本机只读复核：

- 全局 pnpm 自身为 11.23.0，但 package.json 固定 pnpm@11.13.0；在仓库执行 pnpm --version 会尝试该 pin 并报 broken release / @pnpm/exe 缺二进制。
- CI 使用 Node 22，并从 packageManager 安装 pnpm。开发前应选取可用、与 CI 一致验证的工具版本，再处理 pin 和依赖安装；本阶段未替用户改版本。
这是本地观察，不保证云端环境完全相同；共享的版本 pin 仍需验证。访客不需要安装这些工具。
本次未安装依赖、未运行构建或双系统测试；没有上线 world 路由。

## 5. 云端交付规则
本次工作开始时 git ls-files tuvis-world 为空，目录整体未受追踪。书面设计提交可能包含认可方向图作为审阅附件，不等于其余素材已经进入仓库。
必须在交接时重新核对：云端执行仓库/分支能否读到全部必需文件，或是否已附上经过验证的压缩包；不能以“本机路径存在”为完成证据。
归档只收录当前规格、实际使用的资产/数据、来源与提示词、预览、文件清单。历史正面素材只在明确的历史目录或排除清单中保留，不放到默认运行资源入口。
压缩包不携带 node_modules、密钥、缓存或原生建模工具；不把浏览器能识图误写成浏览器能生成缺失素材。
所有路径相对包根；运行时资源通过站点提供，保留现站 /tuvis-website/ base 规则。
