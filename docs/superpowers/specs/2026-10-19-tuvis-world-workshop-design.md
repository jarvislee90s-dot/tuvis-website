# Tuvis World｜斜俯视工坊互动专区设计
版本：v1.0 审阅稿 · 2026-10-19（Asia/Shanghai）
状态：用户已确认核心范围与视觉方向；本文新增细节为 CANDIDATE，整份书面设计尚待批准。
当前阶段：Design → Written Spec Review。尚未进入 implementation plan / 云端实现。

## 1. 目标与成功条件
让第一次接触兔维斯的访客，在电脑浏览器里进入他的工坊，点击地面走动、靠近物件了解世界观，并完成寻找、维修、组装 Bug Buster 的短主线。窗外、居民海报、工具箱与日常小动作共同展示原创 IP 的生活世界。
成功首先看互动是否成立：能走、能绕障碍、能正确遮挡、能操作物件、能完成并重玩任务；画面保持用户已接受的明亮科技轻喜剧风格。

### APPROVED｜已确认
- 采用当前斜俯视方向稿的视角和画风；固定镜头，一期不旋转房间。
- 点击地面移动；点击物件自动走近并互动；界面显示操作说明。
- 首个场景是工坊房间，可自由探索；窗外介绍回路城，海报介绍居民类型，工具箱介绍四件装备与代码编辑类比。
- 主线是寻找物件、维修零件、组装橙色 Bug Buster；有装备特写，完成后可陈列于枪架/武器库。
- 包含坐下、喝咖啡、装备展示等日常互动。
- 外围需要适当渲染世界延伸，不能用黑边/深色虚空直接截断房间；角色不能穿墙、穿家具或进入不可通行区域。
- 电脑网页直接运行；不做手机适配，不要求访客安装客户端或插件。
- 后续执行 Agent 在云端沙箱，能识图但不能假定能生图/建模；必要图片必须在交接前准备并随仓库或附件交付。
- 保留既有故事内容方向：1 本完整故事书＋2 张预告卡。目前素材尚未达到此交付状态。

### 明确替代关系
Bug Buster 替代此前 Merge Prism 的首件组装候选；不改变四件装备的既有设定。
斜俯视方案替代旧正面背景＋立绘方案。旧房间、旧场景坐标和旧 QA 摆放图继续停用。
最新外围要求替代方向稿中的深青色虚空边缘；对视角和画风的认可不等于认可该边缘处理。

## 2. 视觉基准与方案取舍
认可的方向图：[斜俯视工坊](../../../tuvis-world/03_exploration/workshop-isometric-direction-v1.png)。
此图仅确定视角、画风和空间气质：含内嵌角色、前景物件及深色外围，不能直接当运行背景。
相机保持同一斜俯视角度；角色、家具、投影、地面和图片透视必须统一。不要求数学上严格的等距投影，也不能以正面角色替代斜俯视角色。

| 外围方案 | 取舍 | 本稿选择 |
|---|---|---|
| A：建筑剖面与城市环境延伸 | 房间外可见相邻建筑、走廊/露台片段、管线、植被与远景，通行由真实边界限制；需补美术 | 推荐 |
| B：画面紧贴室内裁切，主要从窗口看外界 | 素材量较少，但房间外围的延伸感较弱 | 备选 |
| C：开放到室外游玩 | 新场景、导航、素材与交互明显增多 | 一期不采用 |

推荐 A 为 CANDIDATE：保留房间为唯一游玩区域，外围作为可见但不可进入的环境。外围具体建筑造型不是新世界设定或新地点定名。
一期不需要 Unity、Three.js、真实模型或自由镜头；平面分层素材足以承载确认的体验。未来改为真实 3D 需要重做渲染和相应资源，不承诺无成本升级。

## 3. 外围、碰撞与遮挡
三个范围分别定义：
1. 可见区域：完整画面，包括工坊、外部环境与远景。画面不以纯黑/深色虚空截断房间。
2. 可走区域：房间地面中的连通通道，排除墙、家具、台阶外沿与其他障碍。
3. 可交互区域：物件点击区域与角色可到达的靠近点；不要求角色站进物件图片中心。

用墙体、窗台、封闭门、栏杆、落差与大型设备等环境理由解释边界；它们必须与碰撞数据对齐。若前侧采用建筑剖面，靠内侧的栏杆、花槽或固定设备应表现通行边界，避免在毫无提示的空地边缘停住。
点击窗外、外部楼顶等装饰区域不产生越界移动；可用短提示“先在工坊里逛逛”或既有窗景介绍反馈。
墙体不通行，不能通过把角色盖在墙后伪装成绕行。碰撞负责“能不能过去”，遮挡负责“谁画在前面”。

底图绘制地面、墙和不能从后方经过的背景物件。允许角色前后经过的椅子、矮桌、沙发、花槽等，使用透明独立层，不重复烘焙在底图。按角色脚底与物件地面锚点进行深度排序；大型物件有跨越多个深度的遮挡时，拆分成明确的前后层。背景内已封闭不可达的区域不做虚假动态遮挡。

## 4. 进入、移动与交互
进入后展示操作说明：“点击地面移动”“点击物件，兔维斯会走近并互动”；提供可再次打开的“操作说明”按钮。
不强制观看开场或完成任务才能自由探索；工作台用轻提示引导主线。物件名称在悬停/选中时出现，不能仅靠微弱闪光辨认。

点击有效地面后，从当前位置沿导航路径走到目的地。点击物件后，先走到该物件的靠近点，到达后再触发介绍或动作。只有当前目标可以触发到达事件；新点击取消先前尚未触发的目标。
点击不可走位置时不穿越障碍，也不传送；在合理边界处反馈。存在障碍时绕行；无可达路径则保持原位并提示。
打开阅读、图鉴、维修或组装面板后，暂停场景移动；关闭后恢复到原位置。面板内点击不传播为地面移动。窗口失焦时停止移动与拖拽，避免恢复后突然跳动。

### 导航约定
使用二维场景平面坐标，提供可走多边形、障碍多边形、人工导航节点及连通边。角色脚底为定位锚点，障碍按角色足迹半径留出余量。
点击点与导航图相接时只连接整段可通行的边；通过最短路径选择有效路线。移动过程中检查线段碰撞，避免低帧率或一次大位移穿墙；不只检查最终落点。
实际坐标、角色足迹、物件停靠点必须由最终背景标注，不能套用旧正面 manifest。图片缩放采用等比包含，输入坐标经过真实场景显示区域换算；窗口大小、留边、系统缩放不能改变命中结果。

## 5. 物件与内容
| 物件 | 内容/动作 | 世界观作用 |
|---|---|---|
| 窗户 | 查看回路城与景物介绍 | 世界在工坊外继续存在 |
| 居民海报 | 查看居民类别和简短描述 | 混合型智慧文明；概念人物不自动成为固定配角 |
| 工具箱 | 装备图鉴、领取主线模块 | 工具与代码编辑功能对应 |
| 工作台 | 接任务、维修、装备特写组装 | 发明家的工作方式 |
| 桌椅/休息处 | 走近、坐下、起身 | 日常生活与性格 |
| 咖啡机 | 走近、喝咖啡/持杯、恢复站姿 | 轻松生活气氛 |
| 装备架 | 完成后陈列 Bug Buster，可再次查看 | 可见的完成反馈 |
| 书架/阅读角 | 阅读故事与查看预告 | 故事档案入口 |

长文使用普通网页阅读层，场景负责发现与进入。提供直接打开图鉴/故事的文字按钮，阅读不依赖精确点击小热点。
装备名称与识别色沿用既有资料：Diff Radar（红，差异审查/异常扫描）、Bug Buster（橙，Debug/隔离异常）、Code Weaver（蓝，编写/构建）、Merge Prism（绿，合并/整合）。说明配简短视觉类比，访客不需要懂真实代码。

## 6. 主线设计｜CANDIDATE 细化方案
主线暂名“让 Bug Buster 重新上线”，目标时长约 3–5 分钟；名称和时长为设计提案。
主体固定在工作台，三个外部模块为：瞄准模块、脉冲发射头、能源匣。采用熟悉的“瞄准器、枪头、弹夹位置关系”，能源匣仍属于科幻设备设定。
1. 点击工作台，看到未完成的 Bug Buster 与三模块轮廓，学会物件互动。
2. 工具箱领取瞄准模块，同时可浏览四件装备。
3. 居民海报附近的低置收纳盒取得能源匣；可查看海报，但阅读全文不是拾取条件。
4. 窗边储物位置取得发射头；可顺势查看回路城。
5. 回工作台检查能源匣，在独立维修示意界面选择松动的接口并执行“检查”，通过后恢复供能。示意用代码绘制，不需要云端 Agent 补画破损装备。
6. 进入特写，把三模块装到主体上；完成后能源环亮起，切换完整成品图。
7. 角色展示成品，将它放到装备架；可继续自由探索、再次查看或重玩主线。

三个模块可任意顺序寻找；背包只显示三个任务槽。维修前不能完成能源匣安装，给明确返回维修提示；模块不会因错误操作丢失。日常互动可穿插，不重置任务。
主线是工坊新手体验，不自动作为《完美的一天，差一点》的正式剧情，也不加入未确认的敌人或战斗。

### 装备特写
固定一个清楚的侧向三分之四角度，允许整体放大，不提供自由旋转。
独立模块支持拖到高亮插槽吸附，以及“选零件→点插槽”的等价操作。错误放置回到零件托盘；已安装模块不能重复消耗。
零件归位用位移、轻微平面转角、卡入闪光；独立生成的模块不保证接缝完全一致，最终过渡至完整 Bug Buster 图片。不能把该过程描述为精确 3D 拆装。

## 7. 角色表现｜CANDIDATE
一期准备匹配斜俯视镜头的四个斜向朝向图，移动时选择方向，配轻微起伏与脚下投影；这是轻量走动表现，不是骨骼动画或完整逐帧步态。
坐下、持杯和持装备展示，各准备匹配场景镜头的独立姿态图；采用图像切换和短过渡。起身/结束动作恢复站姿，点击新目的地可结束日常动作。
正面旧姿势只可作为档案/特写插图，不当作场内角色。若四向图或动作图未齐，列为素材阻塞，不能让云端 Agent 临时生成或以正面图冒充。

## 8. 网页接入与职责边界｜CANDIDATE
加入现站语言路由下的 world 专区，导航名称“兔维斯世界”。中文路径为 /zh/world；保留现站 /tuvis-website/ 部署 base。
界面导航维持中英文键对齐；一期世界内容以中文为主。/en/world 同样可以进入，明确标注当前故事/设定为中文，完整英文翻译另行安排。
不修改冻结的 brand/、根 SPEC.md、legacy/，不手改同步生成的 src/content/*.json 或 public/manual/。

| 单元 | 职责 | 输入/输出 |
|---|---|---|
| 场景数据与导航 | 坐标、障碍、靠近点、路线合法性 | 场景定义＋当前/目标脚底点 → 路径或不可达结果 |
| 场景显示 | 背景、物件、角色、投影、深度与缩放 | 素材定义＋位置/姿态 → 画面 |
| 互动控制 | 点击、移动到达、取消、面板与动作 | 用户意图 → 移动/打开内容/日常动作 |
| 任务状态 | 模块领取、维修、安装、完成、重玩 | 明确任务事件 → 状态与可用操作 |
| 内容面板 | 角色、图鉴、世界介绍、故事与组装 | 内容数据＋当前状态 → 可读可操作界面 |
| 资源与存档 | 加载、失败恢复、本地进度 | 静态文件/版本化存档 → 可用资源与有效状态 |

沿用 React、TypeScript、CSS/SVG、Framer Motion、Zustand；无需新增游戏引擎。实际文件拆分与实施顺序在 written spec 批准后的 implementation plan 中确定。
状态分开管理：移动目标、当前面板/日常动作、主线状态。任务阶段由有效模块、维修标志和安装集合推导，禁止互相矛盾的多个“完成阶段”。
素材 manifest 为所有图像路径、裁切、锚点、碰撞、热点、停靠与遮挡的入口；新版本独立建立，不把退休 manifest 改名冒充新版。

## 9. 加载、存档与错误处理｜CANDIDATE
初次加载显示进度与操作说明；核心场景、角色、必要遮挡层未加载完前不进入游玩。装饰资源失败可以跳过；必要资源失败显示可重试提示，不能用一块缺图区域继续假装正常。
浏览器本地存储仅保存版本化主线进度与提示已读状态；不保存无法验证的旧坐标。存档损坏/版本不支持时安全重置并说明，存储被禁用时仍可完整游玩。提供“重玩主线”，重置前说明会清除本地主线进度；不影响官网其他数据。
无账号、服务器存档、排行榜或跨设备同步；无追踪脚本。
首版不把配音或背景音乐作为完成条件；如加入声音，用户操作后启用且可关闭。Tab 可到达阅读/组装按钮，Esc 可关闭面板；简化动态效果设置不改变任务规则。

## 10. 故事内容与交付分界
“1 本完整故事书＋2 张预告卡”仍是已确认内容方向，没有在本稿中静默取消。
现有《完美的一天，差一点》只有六页结构、封面和 P2 候选图；正文与 P3–P6 插图未齐。故事入口可在原型阶段明确显示“故事制作中”及预告，不能把梗概标为完整故事书。
可先验证工坊互动原型；要把整个既定首版内容标为完成，必须补齐完整正文与内页，或由用户明确接受故事延后。此处不默认取得延期批准。

## 11. 验收标准
- 电脑通过正常站点 URL 打开，访客不安装插件/客户端、不填写 API Key、不调用运行时生图或建模服务。
- 画面与认可方向一致；看得见室外延伸；没有直接用黑色虚空截断房间的处理。
- 默认场景固定镜头；角色脚底沿地面移动，不是正面舞台式横向滑行。
- 点击地面到达；点击物件先走近再触发。快速换目标不会触发上个物件；弹窗点击不带动角色。
- 每个任务物件均可达；路线绕开家具，不能穿墙、抄过障碍或因低帧率越界；外部装饰区域不可通行。
- 角色经过前景家具时遮挡正确；脚底、投影、动作停靠与家具位置一致。
- 可以查看窗景、居民海报、四装备图鉴；坐下、持杯和展示装备有可见反馈。
- 领取三模块、维修、安装、陈列和重玩可完整闭环；任意领取顺序不导致卡死。
- 触控板点击操作可完成组装；错误拖放不丢失模块。
- 刷新、无存储权限、资源失败、切换标签页和调整窗口有明确可恢复行为。
- 验证 Windows Chrome/Edge、macOS Chrome/Safari；覆盖 1280×720 及较大桌面窗口，检查 Windows 125%/150% 缩放与 Mac Retina。手机不列入验收。
- 复用现站必要检查：类型检查、既有测试、导航与 i18n 对齐、子路径资源加载；新增有意义的任务状态/导航边界验证。验收记录区分真实系统、浏览器引擎模拟与未测试范围。
- 完整故事交付按第 10 节单独验收，不能以互动原型通过代替。

## 12. 当前缺口与工作流
详细缺口见[就绪清单](2026-10-19-tuvis-world-readiness.md)。
当前可提交审阅的是本设计，不是成品网页或已齐备的云端素材包。核心缺口是符合外围要求的干净斜俯视场景、匹配角色、遮挡层、新版坐标与导航，以及故事内容。
下一步按 superpowers：书面设计审阅 → writing-plans → 用户审阅计划并选择执行方式。计划要把“本地有生图能力的阶段完成素材并验证打包”放在“无生图云端 Agent 开始依赖素材的实现”之前。
不把“可以写代码”与“所有美术已就绪”混为一个状态；当前未达到完整云端交接就绪。

## 13. 本稿需要一并审阅的新增细节
以下均为 CANDIDATE，不冒充此前逐项批准：
C1：外围采用建筑剖面＋城市延伸，只看不进入。
C2：四向静态角色＋轻量位移动效，日常动作采用独立姿态切换。
C3：三个模块的具体分布、能源匣接口维修、任意领取顺序。
C4：自由探索不强制教程、三槽任务栏、本地主线存档与重玩。
C5：沿用现站技术，不新增游戏引擎；首版无必要音频。
C6：界面导航中英对齐，世界正文中文首发，英文入口明确语言状态。
这些细节在整份书面设计获批后成为实现依据；若用户修改其中一项，明确记录替代关系。
