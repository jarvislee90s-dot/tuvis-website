## 1. 目标与本次方向调整

让访客进入兔维斯生活的小环境，通过角色活动、物件互动和轻量任务认识这个原创 IP。专区同时承载角色、装备、世界设定和故事内容。

原资料已确认“轻互动探索型角色专区”，主要通过点击装备、物件与地点展开设定。本次用户进一步明确：网页互动是重心，希望加入轻量游戏属性，让兔维斯能在小场景中活动。这个新方向扩展了原交互目标；保留既有角色和世界设定，不把原四模块内容取消。

## 2. APPROVED｜已确认方向

- 兔维斯是独立原创角色 IP；基调为科技轻喜剧。既有角色与故事素材采用明亮多彩的 3D 动画视觉方向；游戏画面可以另行讨论像素或平面表达。
- 沿用混合型智慧文明、角色外观和四件装备既有设定。
- 本阶段需要规划文档；网站专区需要一个可活动、有小交互的环境，并加入游戏属性。
- 3D 不作为首版硬性条件；用户接受可行的 2.5D 方案，优先先形成能在网站体验的互动世界，未来再提升体验层级。
- 故事书保留，当前可明确推进的图片素材可以先制作。
- 既有第一批故事内容结构：1 本完整故事书《完美的一天，差一点》与 2 张预告卡。
- 首个可活动环境聚焦兔维斯的工坊房间，借房间内的交互介绍世界观。
- 窗外展示外部世界；墙上海报介绍世界中的种族；工具箱展示四件装备及其对应的代码编辑功能。
- 设计一条包含寻找物件、维修零件、组装一件装备的简单主线，在过程中教授基本操作与互动逻辑，并自然引入世界观。
- 加入日常小交互：在桌椅处坐下、到咖啡机处喝咖啡、装备并展示/评估装备。具体动作数量、表现形式与评估机制尚未确定。
- 首件组装装备确定为 Bug Buster｜Bug 清除脉冲炮，利用枪械式外形和模块组装的熟悉感降低理解成本；鲜艳橙色应保留。
- 组装时需要装备特写；完成后可放回枪架/武器库形成陈列反馈。用户不要求首版具备真实 3D 旋转浏览。
- 运行方式为电脑浏览器打开网站直接游玩；访客不需要下载客户端、安装插件或额外运行环境。手机适配和移动端布局明确不在首版范围。
- 后续执行 Agent 不具备第一方生图或建模工具；所需素材与开发环境前置条件必须提前列明，不能把调用这些工具留作默认实现步骤。
- 点击地面移动；点击物件则自动走近再互动。界面显示这两条操作说明。
- 执行环境为云端沙箱，Agent 能识图但不能假定能生图；所有必要图片应提前打包并随仓库/附件交付，不能引用只存在本机的资源。
- 用户所期望的 2.5D 是斜向下俯视、有明显地面纵深的房间探索。此前助手制作的正面工坊加立绘不符合该要求，停止作为首版场景使用。

## 3. 首版体验框架

“一间工坊 + 一个可活动角色 + 一条短主线 + 日常互动”已获用户明确认可。把第一次主线体验控制在约 3–5 分钟仍是候选目标，尚未经用户确认。

已确认的流程方向：进入工坊 → 学会基本移动与互动 → 寻找物件 → 维修零件 → 组装一件装备 → 继续体验工坊日常。窗外、海报和工具箱负责把世界观穿插进这一过程。

这一决定取代上一轮“修好某个小装置”的开放示例，主线终点收敛为组装 Bug Buster。用户选择 Bug Buster，替代助手此前提出的 Merge Prism 候选；Merge Prism 的既有装备设定不变。零件清单、维修方式与具体剧情仍为候选；不自动视为《完美的一天，差一点》的正式情节。

### CANDIDATE｜主线细化建议

主线目标已确定为 Bug Buster。推荐把完整主体固定在工作台上，另找三个容易区分的外部模块：瞄准/传感模块、前端脉冲发射模块、能源匣。三模块名称与结构尚未冻结。沿用用户所说的“瞄准器、枪头、弹夹”的熟悉位置关系，其中能源匣对应这件科幻装备的能量供给。示例流程如下，等待审阅：

1. 在工作台发现未完成的装备与组装图，获得第一个操作提示。
2. 走到工具箱，认识四件装备，找到一件可用部件；目标装备显示为待组装的原型，不伪装成已完成状态。
3. 查看墙上的居民海报，认识不同居民类型；附近放置另一件零件，让寻找过程自然经过这一区域。阅读全部设定不作为拾取条件。
4. 在靠窗区域找到待维修的部件；窗外的回路城提供自然的世界介绍机会。具体维修谜题待定。
5. 回到工作台，在装备特写中完成维修和组装；装备成品做一次简短展示，再放回枪架/武器库。候选试用反馈是隔离工作台上的错误信号，对应 Debug，不额外引入战斗场景。

建议让任务引导行动，世界观介绍保持简短并可继续展开；日常互动可在任务途中使用。是否从进入时就允许自由探索、是否保存进度、如何重玩，尚未确定。

游戏属性首先来自目标、行动、环境状态变化与完成反馈。战斗、复杂养成、多人联机、排行榜和账号系统不作为当前建议范围；若用户选择相关玩法，需要重新讨论范围。

## 5. 三种画面方案

根据用户的素材能力与首版目标，当前技术建议收敛为 B：固定视角的 2.5D 工坊；真实 3D 作为后续升级方向。以下比较保留作选择依据，不表示三种方案都要实现。交互细节仍需审阅。

视角修正：固定视角必须是斜俯视/等距感的房间，能看见家具顶面和地面前后关系；角色也应采用匹配的俯视角度。停止使用 `04_web_assets/scene/workshop-room-v1.png` 的正面房间与对应场景坐标。新方向图 `03_exploration/workshop-isometric-direction-v1.png` 已生成，状态为 CANDIDATE，等待用户审阅；该图含内嵌角色，不是可直接叠加角色的成品背景。

| 方案 | 体验特征 | 主要素材与制作工作 | 取舍 |
|---|---|---|---|
| A｜小型真实 3D 工坊 | 角色在立体房间活动，有遮挡与空间关系；首版可固定镜头 | 角色模型、骨骼/动画、场景模型、材质与性能适配 | 最接近《小王子》的空间体验；当前资料包没有可用 3D 模型 |
| B｜斜俯视 2.5D 工坊 | 固定的斜俯视/等距感视角，地面有明确纵深，角色沿地面前后左右移动 | 无内嵌角色的斜俯视背景、匹配视角的角色图、物件前后遮挡层、可走区域与导航点 | 当前收敛方向；延续现有 3D 渲染画风，不需要真实模型或任意旋转镜头 |
| C｜像素或平面卷轴工坊 | 俯视或横向移动，游戏规则直观 | 新画风场景与角色动作、碰撞地图、物件状态 | 适合扩展关卡与任务；需要重新建立与主视觉一致的像素/平面表达 |

2.5D 在这里指固定视角下的平面分层场景，不指已经具备真实 3D 模型。玩法逻辑可以按场景、物件、任务与反馈拆分，但未来改为 3D 仍需要重新制作渲染、移动及相应美术资源。

### CANDIDATE｜无需 3D 的装备特写与组装

- 走到工作台并互动后，房间中的移动暂时停止，打开独立的组装特写层；离开时回到原位置。
- 固定一个清楚的侧面略带三分之四角度，不提供假装真实 3D 的任意旋转。
- 主体与外部模块使用相同透视的透明图片分层显示。悬停/选择一个模块时，高亮对应插槽并显示用途。
- 推荐鼠标拖拽模块到较宽容的目标区，靠近后吸附；同时提供“选中模块 → 点击插槽”的等价操作，便于触控板使用。错误操作弹回，不丢失零件。
- 模块归位采用位移、轻微缩放/平面转角与卡入闪光；末步能源环亮起，显示完整成品。上述平面动画不能称为模型旋转。
- 成品可以整体放大查看并查看三个模块的说明；如以后需要其他观察角度，必须另备静态角度图或真正的 3D 模型，不从单张图自动推断。
- 完成后在房间的枪架上出现橙色成品，允许再次查看；重装/重玩是否保留需最终确认。

## 9. OPEN｜当前决策树

已确定的根节点：工坊房间作为首个环境；物件承载世界观；寻找、维修、组装 Bug Buster 构成教学主线；同时包含日常小互动；电脑网页直接运行，首版不做手机适配。

2. 任务细节：Bug Buster 的模块清单、寻找位置、维修谜题与特写组装操作。
3. 角色动作：哪些需要独立素材，哪些首版可以采用明确标注的轻量表现；不能把单张角色图说成已具备坐下、喝咖啡和持枪动作。
4. 下层流程：是否强制新手任务、阅读入口与任务的关系、存档/重玩、加载失败与防卡住处理、可访问性、双语范围及验收标准。

先确定上层体验与目标设备，再决定依赖这些选择的细节。本文不替代用户尚未作出的选择。

## 10. 给执行 Agent 的技术与环境准备

### 访客端（APPROVED 约束）

通过正常网站链接在电脑浏览器游玩；不要求安装客户端、Blender、Node.js、插件、模型生成工具或配置 API Key。不依赖运行时生图/建模服务。这里的“无需下载”指无需另装客户端；网页仍会正常加载其代码和图片，不表示首次可断网运行。

### 开发端（已核实事实与技术建议）

- 现站已使用 React 19、TypeScript、Vite、Tailwind、Framer Motion 和 Zustand。固定视角房间、角色平移、交互层、任务状态、分层装备特写，可以采用现有网页技术实现；当前方案不要求新增 Three.js、Unity、Godot、Blender、物理引擎或原生插件。
- 执行 Agent 仍需可用的 Node.js、项目指定的包管理器与仓库依赖；这与访客端无需安装不冲突。
- 本次本机只读核查发现：Node.js 已有，但仓库尚无 `node_modules`；`package.json` 指定的 `pnpm@11.13.0` 在本机启动失败。开工前必须处理包管理器版本/安装问题并安装现有依赖；不能声称本仓库已经可以直接启动。尚未更改版本、安装依赖或验证构建。
- 具体环境记录：本机 Node.js 为 v26.8.1，现站 CI 使用 Node 22；尚无统一 Node 版本声明。执行前应按仓库与 CI 约束明确可用版本并验证。pnpm 的本机报错指向 11.13.0 broken release / `@pnpm/exe` 缺少二进制，不在本规划阶段自行替换 pin。
- 原有 `pnpm dev` 用于本地预览；不能要求访客把源码下载后双击 HTML。现站资源与模块通过 HTTP(S) 提供，并部署在 `/tuvis-website/` 子路径。

- 当前 `tuvis-world/` 不在站点 `public/` 目录，也尚未接入 world 路由。实现时通过项目导入机制或复制派生素材到新的站点资源目录接入；不要直接引用本文中的本机绝对路径。新文件名建议小写英文与连字符，import 大小写必须一致，兼容 Linux 部署环境。

### Mac / Windows 的浏览器差异

首版可共用一套网页代码，无需各做一个系统客户端。建议验收覆盖 Windows Chrome/Edge、macOS Chrome/Safari；这是待确认的验收建议，不是已完成测试。

| 方面 | 方案要求 |
|---|---|
| 鼠标与触控板 | 核心操作不依赖右键、中键或滚轮；拖拽提供点击替代，使用统一指针事件处理拖出组件边界与取消 |
| 键盘 | 如有 WASD/方向键/E 等快捷操作，只在场景获得焦点时处理；避免把 Cmd/Ctrl/Option/Alt 组合设为必要操作，输入框中不截获按键；按需兼容布局与输入法 |
| 浏览器声音 | 如加入声音，在用户点击后启用并可关闭；声音被浏览器阻止时玩法仍完整 |
| Retina、Windows 缩放与窗口尺寸 | 以同一场景逻辑坐标缩放布局和命中区，兼容桌面窗口调整与系统显示缩放；不把原始图片像素等同点击坐标 |
| 丢失焦点与切换标签 | 清空移动按键与拖拽状态，防止角色持续移动；暂停或正确恢复动画计时 |

## 12. 镜头与实时 3D 的追加核查

用户补充：目前的画面仍未满足其期望的俯视空间感；希望参考游戏画面，了解转镜头的依赖，以及《小王子》案例的实现方式；复杂的自由镜头体验可以在一期暂缓。新方向图尚未获认可，不继续假定素材视角已确定。

### 已核实事实

- `https://littleprince.dev/` 当前公开启动 HTML 使用 `createUnityInstance`，加载 Unity 的 loader、framework、WASM 和 data 文件，并在启动前检查 WebGPU 与 `texture-compression-bc`。该案例是 Unity 发布的网页 3D 游戏，不能据此称为 Three.js 项目，也不能推广成所有网页 3D 都必须 WebGPU。
- 未查到可明确直接复用的该游戏公开源项目；作者预告开源不等于已取得项目。没有下载大型游戏资源或模型。
- Three.js 的 OrbitControls 支持绕目标旋转、缩放和平移；BoxGeometry 等基础几何体可由代码建立。因此简单立体房间可以由云端 Agent 编写代码构成，不一定需要先安装 Unity 或手工使用 Blender。
- 完整角色模型、骨骼动作与高品质环境仍是独立资源任务。基本几何体可以证明空间与操作，不自动具备现有角色主图的造型质量。
- 仅有单张场景图片时，不能连续旋转得到未画出的侧面、背面和遮挡关系。平面倾斜、视差不等于绕立体场景观察；预先制作多角度图片切换也需要额外一致素材。

### CANDIDATE｜一期取舍

推荐一期采用用户认可后的固定斜俯视布局，完成地面移动、物件前后遮挡、Bug Buster 主线与日常互动；自由转镜头暂缓。若用户认为旋转或真正立体空间是关键，则另行提出“代码搭简化 3D 小房间”的小规模可行性验证，获得问题与验证方式批准后再执行，不能直接把精美静态图片包装为已可旋转的空间。

开发依赖与访客依赖继续分开：网页 3D 库/引擎的浏览器构建可以随网站加载，访客无需安装；Unity 编辑器、模型工具或新 npm 依赖则属于开发准备，选定方案后明确列出。
